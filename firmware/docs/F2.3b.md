# F2.3b — Safe automatic watering integration

This milestone supersedes F2.3a's shadow-only sketch integration. The pure
watering controller remains independent of Arduino/GPIO. Automatic actuation
is now reachable only after an explicit Serial AUTO command; boot is always
MANUAL/OFF. No AUTO persistence, MQTT, BLE, OTA or NVS is included.

## Confirmed calibration

The maintainer supplied and confirmed these measured distances:

| Setting | Value |
|---|---|
| FULL_DISTANCE | 3.00 cm |
| EMPTY_DISTANCE | 12.26 cm |
| Minimum water | 20% |
| Soil start / stop | <30% / >=70% |
| Maximum continuous pump run | 5000 ms |

`irrigation::confirmedConfig()` provides the installation's configuration.
The general controller still defaults to missing/unconfirmed calibration so
other callers cannot implicitly assume an installation has been calibrated.
Water % = 100*(12.26-distance)/(12.26-3.00), clamped to 0–100.
**0% is the lowest tested safe operating water level, not a physically empty
reservoir.** The 20% threshold is a further reserve above that point. Moving
the SRF05, changing its mounting, or changing the reservoir requires measuring
and explicitly confirming calibration again. Old 4/8 cm trial values are unused.

## Ownership and safety

`irrigation.h/.cpp` coordinates the existing watering controller and pump.
Only pump.cpp writes GPIO23; its verified HIGH=ON/LOW=OFF behavior and independent
5000 ms cutoff are unchanged. Sensor acquisition and GPIO assignments are unchanged.

The watering controller now exposes its existing safety assessment for reuse,
plus notification of a real manual start or interrupted run. Its default
evaluate behavior is unchanged for F2.3a callers. Evaluation with automatic=false
cannot start a run and does not stop a safe manual test just because soil is wet;
it still applies all safety checks, locks and the five-second controller timer.
Both timers use rollover-safe unsigned elapsed time. There is no third timer
in the integration layer.

Before MANUAL or AUTO ON: soil and SRF05 validity flags must be true; soil must
be finite and within 0–100%, distance finite and positive; the shared acquisition
timestamp must be <=4000 ms old; calibration must be confirmed/valid; water must
be >=20%. DHT11 is monitoring-only. A failure during a run requests physical OFF
on the next evaluation and latches LOCKED. Recovery alone cannot restart a dry
plant: only valid fresh soil >=70% clears LOCKED. The same lock also rejects
manual ON until rearmed, preventing a manual bypass of a timed-out run.

The layer checks the physical pump module before evaluating the controller.
A pump cutoff or unexpected OFF interrupts and locks the controller, suppressing
restart on that evaluation. The returned status cannot remain WATERING with
the pump module OFF. Timeout takes priority on its boundary; fresh wet soil may
unlock on a later evaluation. A normal automatic stop at soil >=70% returns IDLE.
Repeated ON/AUTO never retimestamps a running pump. Changing mode while running
stops and locks the previous run; toggling modes does not clear a lock.

"pump state" means the module's commanded GPIO state. There is no contact,
flow or current feedback to prove that physical water flow matches it.

## Serial commands (115200 baud, Newline)

| Command | Behavior |
|---|---|
| AUTO | Enable automatic decisions; safe dry soil may start the pump immediately |
| MANUAL | Immediately request OFF and set MANUAL; no sensor refresh required |
| OFF | Immediately request OFF and set MANUAL; no sensor refresh required |
| ON | MANUAL only, safety-gated, not allowed while LOCKED; maximum 5000 ms |
| STATUS | Report mode, pump, controller state, soil %, soil validity, water %, water validity, reason and remaining ms |

MANUAL/ON does not require soil <30%; it requires valid safe inputs. Wet soil
does not cancel a manual test, but unsafe data and either timeout do.
OFF/MANUAL bypass automatic evaluation so they cannot briefly activate a pump
while processing a stop command. Interrupted runs preserve the lock. Commands
are case-sensitive. Blank lines are ignored; unknown/control-character/overlong
lines are rejected. CRLF is also accepted.

The production sketch uses `SerialCommands::feedLine`, which only assembles
lines, then dispatches through the irrigation safety gate. The original `feed`
wrapper remains for F2.2 low-level regression tests; the deployed sketch does
not use that direct pump-command dispatch. Future command paths must use the
integration API, not low-level pump ON.

The loop services safety before/among Serial input, immediately after sensor
updates before printing readings, and after acquisition/logging. Diagnostics
are emitted for commands, state changes, and at two-second intervals. Sensor
work retains the existing final-250-ms timeout guard and resumes after OFF.

## Remaining risks and supervised hardware checklist

- Check wiring, ECHO divider, installed calibration, supplies/GND, transistor
  bias and relay OFF with the pump load disconnected first. GPIO initialization
  cannot guarantee OFF before setup, during reset, logic power loss or CPU failure.
- Boot/reset and reconnect Serial: verify MANUAL/OFF every time, including after
  a prior AUTO session. STATUS must show missing readings inhibited until acquired.
- With safe water and valid sensors, test MANUAL ON/OFF/MANUAL and the five-second
  cutoff. Try ON repeatedly and at the deadline; no continuous run extension.
- Enable AUTO deliberately. Verify start below 30%, hold through the hysteresis
  band, stop at >=70%, and no ON command override in AUTO.
- Lower usable water below 20% and inject safe sensor failures while running.
  Verify OFF/LOCKED. Restore valid dry readings: no restart. Supply valid wet
  soil >=70%, then dry soil: verify rearming. Mode toggles must not bypass lock.
- Exercise OFF/MANUAL during sensor failure and AUTO execution. Test cutoff under
  missing echoes, DHT faults and Serial load, initially without the pump load.
- Only then perform supervised short pump trials with suitable water and supply,
  and a physical power disconnect available.

Fault response is limited by the two-second acquisition cadence and bounded
blocking DHT/echo/Serial work; stale snapshots are rejected after four seconds.
The five-second cutoff is cooperative software, not a hard real-time physical
guarantee: loop/driver latency exists, and a stalled CPU cannot enforce it.
An independent hardware cutoff is needed for a strict physical deadline.
Soil disconnects can produce plausible ADC values; software cannot detect every
wiring fault. Water percentage assumes a linear distance-to-level relationship,
not calibrated reservoir volume. No hardware feedback verifies pump motion/flow.
