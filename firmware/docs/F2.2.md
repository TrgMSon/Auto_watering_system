## Implementation

`esp32/pump.h/.cpp` owns GPIO23 and the 5000 ms continuous-run limit. Startup
preloads LOW before OUTPUT, before sensor initialization, and never starts the
pump. ON timestamps a new run; OFF writes LOW immediately when processed.
Repeated ON during a run is ignored and never moves its start time, including
an ON processed at the expiry boundary. A separate ON after the run has ended
can start a new test. Unsigned millis subtraction handles rollover.

`pump_serial.h` parses fixed-size lines without blocking reads or allocation.
At 115200 baud use newline, CR, or CRLF and exactly `ON`, `OFF`, or `STATUS`.
Unknown/lowercase/overlong lines and embedded control characters are rejected;
invalid input never starts a run. Commands have no duration argument. Blank
lines are ignored. At most 32 input bytes are consumed per loop iteration.
STATUS reports commanded state and remaining milliseconds, not measured relay
contacts or pump current. No physical feedback sensor is present.

The loop services the timeout before commands and around acquisition. Sensors
continue on the existing two-second schedule. In the final 250 ms of a run,
acquisition is deferred to avoid starting its blocking DHT/echo transaction
near expiry; it resumes after OFF. Serial reports command outcomes and state.
The test guard does not change any sensor conversion or validity algorithms.

This is a cooperative software timeout, serviced by millis in the loop; it is
not an independent hardware cutoff. There is scheduling/Serial/driver latency
and a stalled CPU or firmware cannot guarantee an absolute physical 5.000 s
cutoff. Verify observed cutoff timing under sensor failures and Serial load.
Use an independent cutoff if an absolute physical limit is required.
GPIO startup code alone cannot guarantee fail-safe operation before setup,
during boot/reset, loss of logic supply, or a floating transistor base. External
biasing and the complete circuit must establish OFF in those conditions.

## Hardware verification before accepting F2.2

1. Disconnect pump load. Confirm the installed wiring matches the earlier
   experiment, transistor pinout, supplies/GND arrangement, relay contact use,
   suppression and external OFF bias. Verify the assumed SRF05 ECHO divider.
2. Power on/reset with load disconnected. Verify GPIO LOW and relay OFF;
   repeat with Serial Monitor opened/reset and logic supply interrupted.
3. Send STATUS, then ON. Verify GPIO HIGH and relay actuation; repeated ON
   must not postpone OFF. Measure cutoff around the five-second deadline.
4. Send OFF during a run and verify immediate commanded deactivation. Test
   invalid, overlong, partial, and CRLF input; none should activate the relay.
5. Disconnect DHT/ECHO safely and flood Serial input during a timed run.
   Verify timeout, continuing sensor diagnostics, and preserved invalid flags.
6. Only after unloaded checks pass, perform supervised short pump tests with
   the correct supply, water available, and a physical power disconnect ready.
   There is no automatic low-water/soil interlock in this manual milestone.

The agent has not uploaded firmware, opened a hardware Serial port, or
activated a pump. F2.1 basic hardware verification is reported by the maintainer;
F2.2 physical verification remains to be performed.
