# F2.3c — Bounded cooldown and automatic retries

This supersedes F2.3b's normal-timeout permanent lock. Sensor acquisition,
calibration (FULL 3.00 cm, EMPTY 12.26 cm), safety thresholds, GPIO23 polarity
(HIGH ON / LOW OFF), and the independent pump.cpp 5000 ms cutoff are unchanged.
The measured 0% water point is the lowest tested safe operating level, not a
physically empty reservoir. Recalibrate if sensor mounting or tank changes.

## State and cycle rules

| State | Condition | Result |
|---|---|---|
| IDLE | AUTO, safe/fresh inputs, soil <30% | Start a new full interval, increment automatic attempts |
| IDLE | Otherwise | OFF; unsafe data inhibits activation |
| WATERING | Safe soil >=70% in AUTO | OFF / IDLE, cycle completed, attempts zero |
| WATERING | 5000 ms expires, fewer than 3 automatic attempts | OFF / COOLDOWN |
| WATERING | Third automatic interval expires without achieving safe soil >=70% | OFF / retry-limit LOCKED |
| WATERING | Unsafe input before expiry | OFF / safety LOCKED; discard remaining interval |
| COOLDOWN | Safe inputs, elapsed <30000 ms | OFF, regardless of soil |
| COOLDOWN | Unsafe required input | OFF / safety LOCKED; no automatic resumption |
| COOLDOWN | Elapsed >=30000 ms, AUTO and soil <30% | Start a new full interval if attempts <3 |
| COOLDOWN | Elapsed >=30000 ms, soil >=30% or MANUAL | OFF / IDLE |
| Safety LOCKED | Valid fresh soil >=70% | IDLE, attempts zero; other safety faults still inhibit activation |
| Retry-limit LOCKED | Any sensor value or mode toggle | Remain OFF / LOCKED until explicit safe reset |

All normal activation gates still require valid fresh soil/SRF05, finite
confirmed calibration and water >=20%; DHT11 never blocks watering.
Unsafe data exactly at a first/second timeout produces a safety lock, not a
resumable cooldown. The third interval without a safe wet goal instead retains
retry-limit LOCKED, requiring explicit action. Safe wet data at a timeout
completes the automatic cycle as IDLE, including on interval three.

In 30–70%, an active automatic interval follows hysteresis until >=70% or timeout.
During cooldown, there is no early restart or early transition, even with wet
soil. After the full cooldown, soil >=30% produces IDLE/OFF. Attempts remain
counted in 30–70%; a later dip below 30% consumes the next attempt in the same
cycle. Only achieving >=70% or an explicit accepted reset clears the automatic
budget. This prevents repeated short excursions across 30% from creating an
unbounded cycle. Each started automatic interval counts, including interruptions.

Timing uses rollover-safe uint32 subtraction. Cooldown begins when completion
is evaluated/reconciled, conservatively ensuring a full 30 seconds OFF even
when the physical cutoff was serviced late. Repeated AUTO, ON, STATUS, OFF or
MANUAL cannot reset its timestamp or erase attempts. Normal cutoff synchronization
now notifies controller completion instead of incorrectly treating it as a fault.
Unexpected actuator OFF before timeout still produces a safety lock.

## Manual commands and controlled recovery

Boot remains MANUAL/OFF with zero attempts and no persisted mode. OFF/MANUAL
always stop immediately without acquiring sensors. They interrupt WATERING into
the existing safety lock; when already COOLDOWN they preserve its deadline and
counter. AUTO does not clear locks or counters. Switching a running manual test
to AUTO still stops and safety-locks that run.

Manual ON still requires safe inputs, MANUAL mode and IDLE. It cannot override
COOLDOWN or either LOCKED condition. Manual tests do not increment the automatic
attempt count; their normal five-second timeout also enters COOLDOWN, and they
never automatically restart in MANUAL. As in F2.3b, soil >=70% alone does not
cancel a manually requested test; OFF, faults or runtime do.

`RESET_WATERING` is case-sensitive and fits the existing fixed-size line parser.
It is accepted only with safe/fresh required data and while neither WATERING
nor COOLDOWN. It writes OFF, clears the lock/budget and leaves MANUAL/IDLE.
It **never starts the pump**. After reviewing the cause and conditions, a user
must separately issue AUTO or a safe manual ON. A rejected reset does not change
mode or advance automatic evaluation. It cannot shorten an active cooldown.
It can also explicitly recover a safety lock after repairing the cause. Normal
dry recovery alone never resumes an interrupted interval. A safety lock is
distinguished from retry-limit LOCKED by its reason; the latter never unlocks
merely because soil becomes wet.

## Diagnostics

STATUS retains mode, pump, watering_state, soil_pct, soil_valid, water_pct,
water_valid, reason and remaining_ms. It appends `cooldown_remaining_ms` and
`watering_attempts` (automatic intervals started in the current cycle).
`remaining_ms` remains physical pump runtime left, zero when OFF. Cooldown
remaining is zero outside COOLDOWN. `RETRY_LIMIT_RESET_REQUIRED` identifies a
budget lock; `LOCKED_UNTIL_WET` identifies a safety lock. Command/state diagnostics
and two-second periodic reports retain bounded logging behavior.
Pump state is commanded GPIO state, not measured flow/contact feedback.

## Supervised hardware verification still required

No firmware was uploaded or physical pump activated by the agent. F2.3b relay
verification is maintainer-reported; host tests/compile do not prove F2.3c hardware
behavior. Initially disconnect the pump load and verify:

1. Boot/reset remains MANUAL/OFF. AUTO is only enabled by an explicit command.
2. With safe water and dry soil, measure <=nominal five-second software intervals
   separated by at least nominal 30-second cooldown; verify no early retry under
   repeated commands. Observe the third attempt lock, including soil 30–70%.
3. Wet soil stops active AUTO. Soil >=30% at cooldown expiry stays OFF; >=70%
   completes the cycle. Retry-limit LOCKED remains OFF even if soil becomes wet.
4. Verify missing echo, invalid soil, stale data and low water stop WATERING;
   restored dry readings must not resume the partial interval. Check faults in
   cooldown and safe explicit recovery.
5. OFF/MANUAL stop immediately. ON/reset cannot bypass cooldown. Accepted reset
   stays MANUAL/OFF, and missing/unsafe data rejects reset.
6. Only after unloaded checks, perform supervised short water trials with the
   proper supplies, safe reservoir level and a physical power disconnect ready.

Software cutoffs remain cooperative: sensor/Serial/loop latency exists and CPU
failure cannot enforce a hard physical deadline. Fault recognition is limited
by the existing two-second sampling and four-second freshness budget. Boot code
alone cannot guarantee relay fail-safe behavior; external bias/circuitry remains
necessary. Soil ADC disconnection may look plausible. No pump flow feedback or
volume calibration is added.
