# F2.3a — Automatic watering decisions (shadow only)

`esp32/watering.h/.cpp` is a deterministic C++ controller: inputs are a
F2.1 `sensors::Reading` and an explicit uint32 time, output is a `Decision`.
It imports no Arduino or pump API and has no GPIO calls. DHT fields are ignored.
Configuration is copied at construction, with no NVS or runtime command API.

## Provisional configuration and water conversion

- Start soil <30%; stop soil >=70%; minimum water >=20%.
- Freshness: age <=4000 ms (two F2.1 intervals), configurable. Older or missing
  required readings inhibit watering. Both sensors currently share F2.1's
  acquisition-start timestamp, conservatively including transaction duration.
- Calibration defaults to NaN endpoints and `calibrationConfirmed=false`.
  Both endpoints must be finite, FULL_DISTANCE >=0 and EMPTY_DISTANCE greater
  than FULL_DISTANCE, with a finite span. Explicit confirmation is mandatory.
  No 4/8 cm trial values are used. Constructor tests use synthetic 10/110 cm
  endpoints only, never deployed calibration.
- Water percentage = 100*(EMPTY_DISTANCE-distance)/(EMPTY_DISTANCE-FULL_DISTANCE),
  clamped at 0/100 by endpoint comparisons. Invalid/unconfirmed calibration,
  stale data, false distance validity, nonfinite or nonpositive distance yields
  UNKNOWN (`waterValid=false`, `waterPercent=NaN`). Below 20% inhibits; exactly
  20% is permitted. F2.1 additionally rejects measurements outside its module
  range. Soil requires its validity flag plus a finite value within 0–100%.
  Percentage thresholds and freshness settings are validated too.

## State transitions

| Current state | Condition | Next state / desired output |
|---|---|---|
| IDLE | Any unsafe required input/configuration | IDLE / OFF |
| IDLE | Safe inputs and soil <30% | WATERING / ON |
| IDLE | Soil >=30% | IDLE / OFF |
| WATERING | Elapsed >=5000 ms | LOCKED / OFF |
| WATERING | Sensor/config failure, stale data or water <20% | LOCKED / OFF |
| WATERING | Safe inputs and soil >=70% | IDLE / OFF |
| WATERING | Safe inputs and soil <70% | WATERING / ON |
| LOCKED | Valid fresh soil >=70% | IDLE / OFF |
| LOCKED | Otherwise | LOCKED / OFF |

Timeout has priority if wet soil arrives on the exact deadline: that evaluation
returns TIMEOUT/LOCKED, and a subsequent fresh wet evaluation can unlock.
Unsigned subtraction handles normal millis rollover for both age and runtime;
evaluation must continue regularly (not be suspended for an entire uint32 wrap).
Repeated evaluations never reset an active run's start timestamp.

Safety interruptions during WATERING deliberately latch LOCKED as well, avoiding
dry-soil retry cycles after transient faults. Once locked, a water fault or new
dry soil cannot clear the lock. Unlock needs only valid, fresh wet soil; invalid
water still prevents a later start. The immediate interruption reason is
reported on its transition; subsequent locked evaluations report LOCKED_UNTIL_WET.

## Integration boundary

The sketch retains the latest F2.1 snapshot and evaluates on every loop, so
staleness/timeout do not depend on receiving a new valid snapshot. Serial prints
state, desired output, water validity/percentage and reason when the reason
changes or every two seconds. `auto_output=DISABLED` is always printed.
There is no enabled switch or link from controller output to pump control:
even setting confirmed calibration does not enable physical automatic watering.
WATERING here means a hypothetical decision, not observed/manual pump activity;
its timer is a shadow timer, not an actuator runtime measurement.

Manual ON/OFF/STATUS, polarity and the F2.2 5-second timer are unchanged.
Automatic OFF decisions do not cancel manual runs in this milestone. Only the
existing manual Serial path can activate the pump. A true physical automatic
cutoff remains out of scope. F2.1 conversion/validity code is unchanged.

## Verification

Run existing sensor tests using F2.1 documentation and pump tests using the
updated F2.2 command (now also linking watering.cpp for isolation assertions).
The controller tests need no Arduino mocks or libraries:

```powershell
$wateringTest = Join-Path $env:TEMP 'watering-f23a-test.exe'
g++ -std=c++11 -Wall -Wextra -Werror firmware/esp32/watering.cpp firmware/tests/watering_test.cpp -o $wateringTest
& $wateringTest
git diff --check
```

PASS: F2.1 suite; F2.2 suite plus no-GPIO/manual-isolation assertions; F2.3a
thresholds, hysteresis, water boundaries/clamping, invalid/missing/unconfirmed
calibration, invalid/stale/missing readings, NaN/infinity/ranges, DHT failure,
timeout boundary, rollover, lock/unlock, and interruption/recovery tests.

RAM 22340/327680 bytes (6%). No new dependencies; git diff --check PASS.
